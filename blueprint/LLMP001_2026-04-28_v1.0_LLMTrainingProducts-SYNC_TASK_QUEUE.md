## How this works

- **Before a session:** Save and close any open `.md` files in your
  editor. The agent edits files during sessions; if you have a file
  open and save after the agent has written to it, your editor will
  overwrite the agent's changes. Close first, then start the session.
- **During a session:** Tell the agent what to change in chat. Don't
  edit `.md` files directly while the agent is running. If you need
  to edit a file yourself, say so and the agent will pause on that file.
- **Between sessions:** Your time. Edit `TASK_QUEUE.md`, add tasks,
  reorder, jot notes. Agent isn't running, no conflict.
- **At session start:** The agent reads this file and reports what's next
  (per `SESSION_PROTOCOL.md` step 4).
- **Tier 1** always gets priority. If Tier 1 has open work, that's what
  we work on.
- **Tier 2** gets worked when Tier 1 is blocked or clear.
- **Tier 3** gets worked when Tier 1 and Tier 2 are both clear.
- **You can redirect anytime** — explicit instruction overrides the
  queue.

## Status markers

| Marker | Meaning |
|---|---|
| `[ ]` | Open — not started |
| `[>]` | In progress |
| `[x]` | Done |
| `[~]` | Blocked (note why) |

Keep status markers honest. A `[>]` task that hasn't moved in two
weeks is actually `[~]` (blocked) or `[ ]` (abandoned and lying to you).

## The three-tier model

### Tier 1 — Priority work

The work that pays the bills, ships the product, or is on a deadline.
This is the day-job. If Tier 1 has open work, that's where we are.

Examples (substitute your own):
- Active client engagements / paid work.
- Tools required for active client engagements.
- Time-bound deliverables (deadlines, scheduled releases).
- Infrastructure that, when broken, blocks Tier 1 work.

### Tier 2 — Important but not urgent

Work that compounds in value over time but doesn't have a hard
deadline. Always tempting to skip when Tier 1 is busy. Skipping it
forever is how the system decays.

Examples:
- Continuing-education content / writing / publishing.
- Community engagement / outreach.
- Tooling improvements that aren't urgent today.
- Research that informs future Tier 1 work.

### Tier 3 — Long-term / creative

Work that is intrinsically rewarding but not commercially urgent.
This is where overflow energy goes. Without Tier 3, the operator
burns out. Without Tiers 1 and 2 in good shape, Tier 3 can't get
attention.

Examples:
- Long-form creative projects (books, games, art).
- Experimental tooling that may or may not pan out.
- Personal-development work.

## What NOT to put here

- **Conversation context.** Goes in `MEMORY.md` topic files.
- **Per-tool decision logs.** Goes in each tool's `MAINTENANCE_LOG.md`.
- **Routine sub-task checklists for an in-progress task.** Use the
  agent's task-tracking tools (if your harness has them) for
  intra-session tracking. `TASK_QUEUE.md` is for cross-session work.
- **Pure thoughts/ideas without a "thing to do" attached.** Goes in a
  scratchpad memory file or a Tier-3 project's idea log.

## Maintenance

- Review at the start of every session (per `SESSION_PROTOCOL.md`).
- Move completed items to `[x]` immediately. Don't batch.
- Every 2 weeks (cadence in `SESSION_ENV.md`): scan for stale `[>]`
  items. Kill, demote, or finish.
- Every quarter: review the meta-task above — are completed items
  recurring or one-and-done? Adjust if needed.
