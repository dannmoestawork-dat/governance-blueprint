## Why this file exists

When the operator misuses a technical term, the agent needs to:

1. Answer the question that was actually asked (not the literal
   question). "How do I make my data zero-knowledge proofed?" usually
   means "how do I implement access control" — not "how do I
   implement ZKP cryptography." The agent should answer the *intent*.
2. Surface the correction so the operator can learn the right term.
3. Save the correction so the agent doesn't re-correct the same
   thing forever. (When mastered, the entry retires.)

When the operator gives feedback on how the agent communicates —
"stop summarizing what you just did," "include paths in your asks,"
"don't open with 'honestly'" — that feedback is durable. It lives
here so future-agents read it without the operator having to repeat.

Both halves of the log compound. Terminology corrections build the
operator's domain mastery. Communication patterns make the partnership
sharper. Neither belongs in cross-session memory (those go in
feedback memories) — but the log is where the agent *first* surfaces
them, before they get promoted to memory.

### [Example: Active correction]

```markdown
### Zero-Knowledge Proofs (ZKP)
- **What the operator said:** "How do we make our data ZK-proofed?"
  (YYYY-MM-DD)
- **Correction:** **Zero-Knowledge Proofs** are a specific
  cryptographic protocol — one party proves they know a secret
  without revealing it. Used in blockchain, privacy auth.
  What the operator means is **access control + secrets management +
  data classification** — making sure people only see what they're
  authorized to see, and sensitive values never leak. The *instinct*
  is correct; the *term* is wrong.
- **Key terms to know:**
  - **RBAC (Role-Based Access Control)** — permissions assigned by
    role, not by individual.
  - **Secrets management** — keeping API keys / credentials in
    `.env` files, never in version control.
  - **Data classification** — labeling content by sensitivity level.
  - **ZKP** — cryptographic proof protocol. Not needed here yet.
```

## Section 4 — Communication Patterns — What Works

Two-way patterns. The operator notices what the agent does well
(or poorly); the agent notices what the operator does well (or
poorly). Both get logged.

### Operator strengths

What the operator does that makes work easier. The agent should
recognize and reinforce.

Example shape:

```markdown
- **[Pattern]:** [What the operator does. Why it helps.]
- **[Pattern]:** [What the operator does. Why it helps.]
```

### Operator growth areas

Where the operator could communicate more effectively with the agent.
Phrased as growth, not criticism — and only logged if the operator
asks for it. (Don't unilaterally write a "things you do wrong" list.)

### Agent improvements

Operator feedback on the agent's communication. Things to do more of,
things to stop. *These are usually promoted to feedback memories,
but the log is where the operator surfaces them first.*

Example shape:

```markdown
- **YYYY-MM-DD — [Issue]:** [What happened. What the operator wants
  instead. (If durable, promoted to `feedback_<topic>.md` memory.)]
```

### File safety patterns

Patterns that prevent data loss. Worth keeping near the top.

Example shape:

```markdown
- **Save and close .md files before sessions.** The agent edits
  files during sessions; if you have a file open in your editor and
  save after the agent has written to it, your editor overwrites the
  agent's changes.
- **Use [your harness's diff/preview feature] before accepting**
  large file rewrites.
- **Cloud-sync version history is a safety net, not a backup
  strategy.** Treat it as last-resort recovery; don't rely on it
  as your durability layer.
```

## Why the log isn't memory

Subtle distinction:

- **Learning_Log** is the *first place* an operator-correction or
  communication-feedback gets written. It's the operator's working
  list of things they're learning + things they want from the agent.
- **MEMORY** is where *durable* corrections get promoted. A
  one-time correction that the operator immediately internalizes
  doesn't need to live in memory. A standing correction ("never use
  X term") gets promoted to a feedback memory after it's been seen
  twice.

The log is the *staging area*. Memory is the *long-term store*.

When in doubt: log first, promote to memory if it recurs.
